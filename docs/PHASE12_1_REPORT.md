### 🟡 Hardening
- **14** الحد المسبق للمعدل **قبل** `get_or_create`: سيل معرّفات لا يمسّ القاعدة (اختبار يعدّ الاستدعاءات).
- **15** `broadcast_rate_per_second` كان رقماً بلا أثر؛ صار يضبط الفاصل بين الرسائل فعلاً.
- **17** `notify_admins` ⇒ نسخة إلى قناة التنبيهات (الإعداد `admin_alert_chat_id` ثم `ADMIN_ALERT_CHAT_ID`)؛ best-effort في الذاكرة، والتنبيه الدائم يبقى عبر الطابور.
- **18** المزود الوهمي مخفي ومرفوض في الإنتاج؛ يُفعَّل فقط في الاختبارات و`demo_cycle`.
- **20** ذاكرة `AbuseGuard` محدودة (10,000 مدخل) ولا تُسقط الموقوفين.
- **21** حد 10MB لاستجابة المزود بقراءة تدفقية (مؤقت، أو «غير مؤكد» بعد طلب شراء).
- **22** `_as_int` بـDecimal: يرفض الكسور وNaN/Infinity والأسس الهائلة (كان `1e400` يرفع `OverflowError`، و`100.5` يُقرَّب بصمت).
- **23** سياسة `partial` موثّقة في RUNBOOK (تقريب لأسفل، مرة واحدة، تعطيلها بالإعداد).

## تغييرات سلوكية عند الترقية (مهمّة)
1. مزودو USD بلا سعر صرف يصبحون **غير صالحين** حتى تضبط السعر؛ طلباتهم تبقى `pending`.
2. تغيير `currency_code` يستلزم مراجعة الأسعار؛ تغيير سعر الصرف يلزمه «🔄 مزامنة».
3. الخدمات غير `default` تُعطَّل عند أول مزامنة.
4. بعد إعادة التشغيل يرسل المستخدمون `/start` (المحادثات بالذاكرة).
5. الإذاعة تعمل الآن بوتيرة `broadcast_rate_per_second` (20/ث افتراضياً).
