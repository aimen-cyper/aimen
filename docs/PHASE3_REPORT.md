# تقرير المرحلة 3 — واجهة المستخدم في تيليجرام + المهام الدورية

**الإصدار:** `0.4.0-phase3` · **الحالة:** مكتملة وجاهزة للمراجعة · **الاختبارات:** 513 ناجحاً / 0 فاشلاً

## 1. ملخص تنفيذي

المرحلة 3 ركّبت **الواجهة العربية الكاملة للعميل** فوق منطق العمل الذي بُني في المرحلة 2،
وشغّلت **المهام الدورية (JobQueue)** التي تجعل الطلب يمشي لوحده حتى حالته النهائية.

البوت الآن قابل للتشغيل فعلياً بأمر واحد:

```bash
python -m main
```

ومن داخل تيليجرام يستطيع العميل: التسجيل تلقائياً → تصفح التصنيفات والخدمات → إنشاء طلب
(رابط ← كمية ← ملخص ← تأكيد) → متابعة طلباته وإلغاء ما لم يُرسل بعد → عرض المحفظة وسجل
العمليات → طلب شحن رصيد بإثبات → فتح تذاكر دعم والرد عليها → قراءة إشعاراته.

**ما لم يُبنَ بعد (مقصود):** لوحة الأدمن داخل تيليجرام (المرحلة 4). لذلك اعتماد طلبات
الشحن ما زال يتم من طبقة الخدمات/السكربتات لا من واجهة أدمن.

**الأرقام:** 14 ملفاً إنتاجياً جديداً + 5 مُحدَّثة (4,221 سطراً) · 8 ملفات اختبار جديدة
(2,024 سطراً) · 196 اختباراً جديداً (317 ← 513).

## 3. ما نُفِّذ — القرارات المهمة

**1) ترتيب المعالجات محسوم ومختبَر.** المحادثات تُسجَّل قبل الأوامر العامة حتى تلتقط
`/start` و`/cancel` أثناء المحادثة؛ والمسارات الاحتياطية آخر القائمة في **نفس المجموعة**
(لا في مجموعة لاحقة) حتى لا تُرسل رسالة «زر مجهول» بعد كل ضغطة ناجحة.

**2) لا زر بلا وظيفة — مُثبت آلياً.** اختبار `test_no_dead_buttons` يبني كل لوحات الواجهة
(52 زراً) ويتأكد أن لكل زر معالجاً مسجَّلاً، وأن لا زر يلتقطه معالجا شاشة في آن واحد،
وأن كل زر ضمن 64 بايت وبإصدار `callback` الحالي.

**3) الضغط المزدوج لا يُنشئ طلبين.** `client_request_id` يُولَّد عند بدء المحادثة لا عند
التأكيد، وطبقة الخدمات ترفض التكرار — مُختبَر صراحةً.

**4) أخطاء العمل لا تُسقط المحادثة.** `@guarded` يعرض الرسالة العربية ويُرجع `None`، فيبقى
المستخدم في نفس الخطوة ويعيد الإدخال (مثال: كمية خارج الحدود).

**5) لا خطأ صامت.** المعالج العام يسجّل كل استثناء غير متوقع في اللوق وجدول `error_logs`
ويُبلغ المستخدم؛ وأخطاء الشبكة المؤقتة تُسجَّل كتحذير فقط حتى لا تُغرق الجدول؛ وحظر
المستخدم للبوت يُعلَّم في القاعدة فتتوقف محاولات الإرسال إليه.

**6) الإشعارات عبر طابور لا إرسال مباشر.** العملية المالية لا تنتظر الشبكة: الإشعار يُكتب
في نفس معاملة العملية، ومهمة دورية ترسله وتصنّف فشلها.

**7) نسخة واحدة فقط.** قفل ملف عند الإقلاع يمنع تشغيل بوتين على نفس القاعدة.

**8) `drop_pending_updates=True`.** بعد توقف طويل لا نُنفّذ ضغطات أزرار قديمة على حالة
تغيّرت؛ الطلبات نفسها تُستأنف من قاعدة البيانات لا من التحديثات المتراكمة.

**9) كل الفترات الزمنية من قاعدة البيانات.** `notification_dispatch_seconds` ·
`order_submit_interval_seconds` · `order_check_interval_seconds` — قابلة للضبط من الإعدادات
مع حد أدنى 5 ثوانٍ يمنع إغراق النظام بقيمة خاطئة.

## 5. طريقة التشغيل

```bash
cd smm_bot
python -m venv .venv && source .venv/bin/activate      # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
python -m scripts.init_db --gen-key                    # ولّد مفتاح التشفير وضعه في .env
# املأ في .env: BOT_TOKEN من BotFather · SUPER_ADMIN_IDS معرفك في تيليجرام · ENCRYPTION_KEY

python -m scripts.init_db                              # إنشاء قاعدة البيانات وزرع الإعدادات
python -m scripts.boot_check                           # فحص شامل قبل التشغيل (بلا تيليجرام)
python -m main                                         # تشغيل البوت
```

ثم أرسل `/start` للبوت في تيليجرام.

**ملاحظة مهمة للتجربة:** الكتالوج يبدأ فارغاً (لا مزودين ولا خدمات ولا طرق دفع)، ولوحة
الأدمن تأتي في المرحلة 4. لرؤية الواجهة بمحتوى الآن استخدم `python -m scripts.demo_cycle`
(قاعدة بيانات منفصلة مؤقتة) أو أضف صفوفاً عبر طبقة الخدمات.

**الإيقاف:** `Ctrl+C` — يُغلق المهام والقاعدة ويحرّر القفل بنظافة.

## 7. المشاكل والقيود المعروفة

1. **تحذير `PTBUserWarning` عند الإقلاع** (`per_message=False`): متوقع ومقصود — محادثاتنا
   تخلط أزراراً ورسائل نصية. تركناه ظاهراً بدل كتمه لأن كتم التحذيرات عادة سيئة.
2. **حالة المحادثة في الذاكرة فقط**: إعادة تشغيل البوت أثناء محادثة تُفقد خطوتها؛ المستخدم
   يرسل `/start` ويبدأ من جديد. لا أثر مالي لأن الخصم لا يحدث إلا عند التأكيد. (الحفظ
   الدائم `PicklePersistence` قرار مؤجل للمرحلة 9.)
3. **لا لوحة أدمن بعد**: اعتماد/رفض طلبات الشحن والرد على التذاكر من واجهة تيليجرام يأتي
   في المرحلة 4؛ الآن المنطق موجود وقابل للاستدعاء برمجياً فقط.
4. **المزودون غير مُفعَّلين**: `api_type` الحقيقي (`perfect_panel`) يُنفَّذ في المرحلة 5؛
   الموجود الآن مزود وهمي للاختبار فقط. مهمة الإرسال تعمل لكنها بلا مزود حقيقي ترفض الطلب
   وتسترجع المال بأمان.
5. **حد الاستخدام في الذاكرة**: يُصفَّر عند إعادة التشغيل — مقبول لأنه حماية من الضغط لا سجل.
6. **الوسائط المدعومة في التذاكر والإيصالات**: صور ومستندات فقط (لا فيديو/صوت) — توسعتها
   سهلة لاحقاً عند الحاجة.
