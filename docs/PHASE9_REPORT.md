## 3. ما نُفِّذ فعلياً

### 3.1 الصلاحيات والهرمية
- **هرمية الإدارة:** `super_admin > admin > support > user`. لا يُنفَّذ إجراء إداري (حظر/فك حظر/تغيير دور/ملاحظة…) على من هو **بمستوى أعلى أو مساوٍ** إلا الأدمن الأعلى — `hierarchy_denied`.
- **منع التصعيد:** لا تغيير لدورك أنت (`self_role_change_blocked`) ولا رفع أحد لدور ≥ دورك (`role_escalation_blocked`).
- **حماية آخر أدمن أعلى:** `set_role` يرفض تنزيل آخر أدمن أعلى فعّال (`last_super_admin_protected`)، و`create_admin` يتطلب `--force`.
- **الصلاحيات:** لا تعديل لصلاحياتك أنت، ولا منح صلاحية لا تملكها، ولا منح صلاحية **خطِرة** إلا للأدمن الأعلى.
- **الحظر:** الحظر الذاتي وحظر الأدمن الأعلى مرفوضان دائماً (`ValidationError`)، والهرمية تُطبَّق على غيرهما.
- كل رفض يُسجَّل في `audit_logs` بالإجراء `security.<event>`.

### 3.2 حواجز المال
- **عينان على كل عملية:** لا يعتمد الأدمن/يرفض شحنته، ولا يعدّل رصيد نفسه، ولا يسترجع/يلغي/يُفشل طلباته — يُعطَّل فقط بالإعداد `security_block_self_actions=false` (للاختبار).
- **over-credit:** المبلغ المعتمد يدوياً لا يتجاوز `amount_units` الذي حوّله العميل (`over_credit_blocked`).
- **سقوف التسوية اليدوية** (لغير الأدمن الأعلى): `admin_adjust_max_units` للعملية (افتراضي 500,000.00) و`admin_adjust_daily_max_units` لليوم (2,000,000.00)، صفر = بلا سقف. القراءة والإدراج داخل **معاملة واحدة** فلا يتجاوز طلبان متزامنان السقف.
- لم يُمسّ مبدأ الخدمة المركزية الواحدة للرصيد.

### 3.3 SSRF
- **عند الحفظ:** https فقط، منفذ 443/8443، بلا بيانات اعتماد في الرابط، بلا `localhost`/`.local`/`.internal`، وعناوين IP حرفية عامة فقط (يُرفض الخاص/loopback/link-local/metadata/IPv6 المُدمج).
- **عند الإرسال:** حلّ DNS ورفض أي عنوان غير عام (`ProviderPermanentError`)، بكاش 300ث. التحويلات 3xx خطأ دائم.
- الفحص الثاني يعمل فقط حين **لا** يُحقن عميل httpx (أي في الإنتاج) كي لا تتعطل الاختبارات.

### 3.4 التحقق من الإعدادات
`SettingsService.set` يمر عبر `SETTING_RULES`: تطبيع الأرقام الهندية، نطاق لكل إعداد، وعلاقات (مثل `min_deposit ≤ max_deposit`). القيمة المرفوضة لا تُحفظ ولا تُبلَّغ للمراقبين. فشل مراقب لا يُبطل الحفظ ويُسجَّل.

### 3.5 إساءة الاستخدام
حدود بالدقيقة: عميل `rate_limit_actions_per_minute` · أدمن `rate_limit_admin_actions_per_minute` (120) · حسّاس `rate_limit_sensitive_per_minute` (8: تأكيد مالي، إنشاء طلب، شحن، تذكرة). المخالفة الأولى تُحذَّر، وتكرارها `rate_limit_strikes_before_block` (5) خلال 10 دقائق يوقف المستخدم `rate_limit_block_minutes` (5) ويُتجاهل **بصمت**. الأدمن يرى الموقوفين ويرفع الإيقاف (`security.manage` — أدمن أعلى فقط).

### 3.6 المحادثات
كل محادثات المشروع (29) تُبنى عبر `conversation(...)`: مهلة 900ث، عند انتهائها تُمسح بيانات المسارات الخمسة ويُبلَّغ المستخدم، فيصير الزر القديم «منتهياً» لا ينفّذ شيئاً. تمرير مهلة يدوية يرفع `ValueError`.

### 3.7 الأسرار والملفات
- `Config.load` يتحقق من صيغة التوكن ومفتاح Fernet و`SUPER_ADMIN_IDS` (معرّفات موجبة) ويسجّل الأسرار لتنقيتها من أي لوق.
- `RedactingFormatter` ينقّي **السطر النهائي كاملاً** بما فيه traceback.
- **لا يُسجَّل نص الرسائل العادية** للمستخدمين (نوع التحديث ومعرّفاته فقط).
- umask 077 عند الإقلاع، و`chmod 0600` للقاعدة وWAL/SHM و`.env`، `0700` للمجلدات؛ تحذير (لا إيقاف) إن تعذّر.

### 3.8 الموثوقية
- **إعادة جدولة حيّة:** تعديل أي إعداد في `JOB_SETTING_KEYS` يعيد جدولة المهمة المعنية فوراً دون فقد عدّادات `JobStats` — **هذا يُغلق قيد «يحتاج إعادة تشغيل» الذي ذكرتُه في م6 و م8.**
- **تنبيه الأخطاء:** أول خطأ غير متوقع من كل «بصمة» يصل لمن يملك `logs.view` بنص منقّى بلا traceback، ثم يهدأ `error_alert_cooldown_minutes` (15). يُعطَّل بـ`error_alert_enabled`.

### 3.9 شاشة «🛡️ الأمان» (`/admin ← 🛡️ الأمان`)
ملخص (فحوص ✅/⚠️/⛔ + عدّادات 24 ساعة + أكثر المحاولين بلا صلاحية) · الأحداث الأمنية (مُصفَّحة) · الموقوفون مؤقتاً (+ رفع الإيقاف) · طاقم الإدارة. كلها بيانات حقيقية من `audit_logs` وقاعدة البيانات؛ لا قيم أسرار.

## 7. ⚠️ تغييرات تغيّر سلوكاً قائماً (يجب أن تعرفها)

| التغيير | الأثر العملي |
|---|---|
| **حظر التنفيذ الذاتي** | أدمن لا يعتمد شحنته ولا يعدّل رصيده. إن كان عندك **أدمن واحد فقط** ويشحن حسابه للتجربة فسيُرفض — استعمل حساباً ثانياً أو أوقف `security_block_self_actions` مؤقتاً |
| **سقف over-credit** | لا يمكن اعتماد مبلغ أكبر من المحوَّل (كان مسموحاً) |
| **سقوف التسوية** | الأدمن العادي مقيَّد بـ500,000 للعملية و2,000,000 لليوم؛ الأعلى مستثنى |
| **قيود SSRF** | مزوّد برابط http أو منفذ غير 443/8443 أو عنوان داخلي **يُرفض عند الإنشاء**. المزودون **الموجودون** لا يُعاد فحص بروتوكولهم/منفذهم (لا مسار لتعديل الرابط أصلاً)، لكن فحص DNS وقت الإرسال يرفض أي مزوّد يشير لعنوان غير عام؛ وفحص «اتصال المزودين» في شاشة الأمان و`security_check` يكشف المزود الفعّال غير https (المنفذ غير مفحوص للقديم) ⇒ أعد إنشاءه |
| **تحقق الإعدادات** | قيم كانت تُقبل (صفر لحد الاستخدام مثلاً) تُرفض الآن |
| **حظر مؤقت** | مستخدم يكرر تجاوز الحد 5 مرات/10 د يُتجاهل 5 دقائق **بصمت**. الإيقاف **في الذاكرة** فيزول بإعادة التشغيل (مقصود) |

| **تحقق التوكن/المفتاح** | `.env` بتوكن/مفتاح بصيغة خاطئة (مسافة أو اقتباس) يفشل الإقلاع برسالة عربية واضحة بدل فشل غامض لاحقاً |

## 8. المشاكل والقيود المعروفة

1. **لم يُجرَّب على تيليجرام الحقيقي** (لا بيئة بتوكن). التحقق عبر `FakeBot` وتطبيق PTB حقيقي لمسارات الجدولة.
2. **DNS rebinding:** فحص DNS وقت الإرسال ثم اتصال httpx يحلّان الاسم مرتين؛ مهاجم يتحكم في DNS قد يبدّل الإجابة بينهما. تخفيف: https + منفذ مقيَّد + كاش. الحل الكامل (تثبيت IP في الاتصال) ممكن لكنه يعقّد TLS/SNI — لم أنفّذه.
3. **الحظر المؤقت في الذاكرة:** يزول بإعادة التشغيل، ولا يتشارك بين عمليتين.
4. **افتراض عملية واحدة** (كما في م8).
5. **لا 2FA للأدمن:** من يسرق حساب تيليجرام لأدمن يملك صلاحياته ضمن السقوف والهرمية.
6. **سقف التسوية بالعملة الداخلية** (وحدات `MONEY_SCALE`) وليس لكل عملة.
7. **تنقية الأسرار تعتمد على أنماط وعلى ما سُجِّل منها:** سرّ بصيغة غير معروفة لم يُسجَّل لن يُنقّى من نص حر.
8. قيود مفتوحة من قبل: لا failover بين مزودين (قرارك) · الإذاعة نص/صورة و`send_photo` غير مجرَّب حقيقياً · الملخص اليومي أرقام فقط وبحث المستخدمين بلا اسم المستخدم (م10) · تكرار إثبات الدفع (`file_unique_id`) لم يُحسم · عملة/سعر صرف لكل طريقة شحن غير منفَّذين.

*قيدان أُغلقا في هذه المرحلة:* `settings.set` بلا تحقق، و«فترات المهام تحتاج إعادة تشغيل».

## 10. الالتزام بالقواعد الملزِمة

| القاعدة | التطبيق |
|---|---|
| تعليقات عربية بجانب كل دالة | كل دوال الملفات الجديدة موثّقة |
| فحص الصلاحية على الـcallback | معالجات الأمان `@admin_required(...)` + اختبار أن الدعم لا يصل |
| صلاحيات من قاعدة البيانات | `security.*` مزروعة في `role_permissions`؛ الهرمية لا تستثني أحداً بمعرّف ثابت |
| تأكيد ثانٍ للحرج | رفع الإيقاف يتطلب `security.manage` (أدمن أعلى) |
| تدقيق بقيم قبل/بعد | كل حدث أمني وتعديل إعداد مدقَّق |
| ممنوع تغيير الرصيد من عدة ملفات | السقوف داخل `WalletService` نفسه |
| لا `except: pass` ولا إخفاء أخطاء | أخطاء المراقبين/التنبيهات تُسجَّل ولا تُبتلع |
| لا أسرار hard-coded / لا API Key كاملاً | التنقية في اللوق وفي تنبيهات الأدمن؛ شاشة الأمان بلا قيم |
| لا أزرار بلا وظيفة | فحص آلي يشمل لوحات الأمان الـ7 |
| المال أعداد صحيحة | السقوف بوحدات صحيحة |
